Detailed Description

class fss::Vdpf< in_bits, Group, Prg, XorHash, Hash, In >

2-party VDPF scheme.

Gen() and scalar Eval() support host and device calls when their backends do. CPU full-domain, range, and proof accumulation run on the host. The Gpu methods launch asynchronous device evaluation. Prove(), EvalAll(), and EvalRange() use chain accumulation. ProveMerkle(), EvalAllMerkle(), and EvalRangeMerkle() use a Merkle fold over a fixed ordered sequence. Both parties must use the same accumulator, key configuration, and ordered inputs. Chain and Merkle proofs have the same representation but different values. XorHash receives (packed coordinate, clamped leaf seed), in that order. Every coordinate bit is message data. Bit 0 of the seed's fourth word is reserved and passed as zero; the built-in backends use it for digest tags. Verification guarantees require the assumptions and accumulator-specific proof conditions in doc/vdpf_merkle_fold_security.md.

Evaluate an arbitrary ordered query sequence and produce a chain proof from split correction words.

One call over xs: Eval() for every input in the order given, then Prove() over the corrected per-point hashes in the same order. The result is bit-identical to calling Eval() per input and Prove() over the results on the same ordered xs. The order of xs is part of the contract: both parties must supply the same sequence, including duplicates.

The cost is not EvalAll()'s. A query sequence that is not a tree-structured set cannot prune, so every input pays its own root-to-leaf walk, exactly as Eval() does. This call does not inherit EvalAll()'s property of visiting each internal node once.

Internally buffers the corrected per-point hashes, 64 B per input.

xs may be any nonempty sequence of inputs in [0, 2^in_bits), including sparse, unsorted, or repeated inputs. Both parties must use the same sequence, including its order and length, and the same proof accumulator and hash configuration. Both servers must obtain the same xs by a path the client cannot split. Any verification guarantee is restricted to the evaluated input values and requires the scheme's security assumptions. See doc/vdpf_merkle_fold_security.md for assumptions and instantiation limits. Layer i is read from cws[i*stride] and the terminal from cws[in_bits*stride]. Packed bit i of tr is the right-control correction at layer i, and the left-control correction is the LSB of the layer's cws entry, exactly as the component form of Gen() writes them. Bits of tr at and above in_bits are ignored.

Precondition

The four cs blocks are not jointly all zero.

Launch batch evaluation of an arbitrary ordered query sequence with the Merkle-fold proof, from split device arrays.

The outputs and proof match host BatchEvalMerkle() bit for bit on the same ordered xs, for any query sequence: sparse, unsorted, or duplicated. The order of xs is part of the contract; both parties must pass the same sequence and agree on the Merkle accumulator. Chain accumulation over a query sequence stays on the host, in BatchEval().

The cost is not EvalAll()'s: a sparse query set cannot prune the tree, so every input pays its own root-to-leaf walk and no frontier is shared. That is why this entry takes no frontier_depth. Group, Prg, XorHash, and Hash must support device execution.

Takes the raw key components s0, cws, tr, and cs as Gen() returned them. Layer i is read from cws[i*stride] and the terminal from cws[in_bits*stride]. Packed bit i of tr is the right-control correction at layer i, and the left-control correction is the LSB of the layer's cws entry, exactly as the component form of Gen() writes them. Bits of tr at and above in_bits are ignored. Uses caller-owned device arrays and backend resources. Temporary node buffers with 32*(M + ceil(M/2)) scratch bytes for M inputs are allocated and released on stream. No upload, deep copy, or synchronization occurs. Backend resources must support concurrent device calls and remain valid until the stream completes. The host instance supplies backend values.

xs may be any nonempty sequence of inputs in [0, 2^in_bits), including sparse, unsorted, or repeated inputs. Both parties must use the same sequence, including its order and length, and the same proof accumulator and hash configuration. Both servers must obtain the same xs by a path the client cannot split. Any verification guarantee is restricted to the evaluated input values and requires the scheme's security assumptions. See doc/vdpf_merkle_fold_security.md for assumptions and instantiation limits. Each occurrence of a repeated input contributes its own leaf.

Evaluate the inclusive range [first, last] and produce a chain proof from split correction words.

Under the VDPF security assumptions, successful verification guarantees at most one nonzero reconstructed output within this range, except with negligible probability. It makes no guarantee outside the range. Layer i is read from cws[i*stride] and the terminal from cws[in_bits*stride]. Packed bit i of tr is the right-control correction at layer i, and the left-control correction is the LSB of the layer's cws entry, exactly as the component form of Gen() writes them. Bits of tr at and above in_bits are ignored.

Launch range evaluation and the canonical ordered-sequence Merkle fold from split device arrays.

Uses caller-owned device arrays and backend resources. Internal scratch is allocated and released on stream. No upload or synchronization occurs. Backend resources must support concurrent device calls and remain valid until the stream completes. The host instance supplies backend values. frontier_depth is relative to each aligned evaluation subtree, capped at its depth. Deep subtrees are split privately to leave at most eight tail levels and a block-root depth of at most 30. threads_per_block is a power of two in [1, 1024], capped at each subtree frontier width. Evaluation fuses share conversion and corrected leaf hashing. The ordered fold uses two buffers with 32*(M + ceil(M/2)) scratch bytes for M inputs, plus 16*M output bytes. These payload sizes exclude allocator overhead. The leaf kernel keeps a bounded depth-first pending-sibling stack of at most eight int4 states per thread and threads_per_block int4 shared frontier states per block. Layer i is read from cws[i*stride] and the terminal from cws[in_bits*stride]. Packed bit i of tr is the right-control correction at layer i, and the left-control correction is the LSB of the layer's cws entry, exactly as the component form of Gen() writes them. Bits of tr at and above in_bits are ignored. The proof uses actual inputs in increasing order and carries odd nodes. Both parties must agree on the range, order, and Merkle mode externally.

Generate correction words in a caller-strided layout and packed control bits.

Layer i is stored at cws[i*stride] and the terminal at cws[in_bits*stride]. tr receives root-order packed right-control bits: bit 0 is the root layer, bit i belongs to layer i, and bits at or above in_bits are zero. The layer LSB keeps the left-control correction. The terminal is stored unchanged as a plain int4. The default stride of 1 stores the correction words contiguously.

Retrying a failed attempt
On return 1, draw two fresh independent uniformly random seed blocks from a cryptographically secure random generator, replace both s0s entries, and call Gen again with the same a and b_buf. Incrementing seed words is not resampling. The caller chooses the attempt limit and handles exhaustion. Reuse of the output buffers is allowed, but discard all cws, tr, and cs values from a failed attempt. Only outputs from a successful call form a key.

Proof accumulation method (Merkle fold).

Parallel alternative to Prove() over a fixed ordered sequence: hashes corrected per-point hashes into the leaves of a binary Merkle tree over the given sequence and folds adjacent nodes with the same hash level by level (an odd trailing node carries to the next level unchanged). The proof is {root, cs[2], cs[3]}, the same 64B shape as the chain's, so Verify() is shared. Every level is an OpenMP parallel batch honoring par_depth, so a par_depth of 0 makes the fold sequential. See doc/vdpf_merkle_fold_security.md.
