2-party VDPF scheme.

Template Parameters

GroupType for the output domain. See Groupable.
PrgSee Prgable.
XorHashSee XorHashable. Paper's \(H\): maps \((x, s)\) to \(4\lambda\) bits.
HashSee Hashable. Paper's \(H'\): maps \(4\lambda\) bits to \(2\lambda\) bits.
InType for the input domain. From uint8_t to __uint128_t.

Full domain evaluation method.

Evaluate the key on each input, i.e., 0b00...0 - 0b11...1. Store the outputs sequentially and accumulate the proof.

Parameters
bParty index. False for 0 and true for 1.
keyThe party's key returned by Gen().
ysPre-allocated output array. Its size must be at least 2 ** in_bits.
piProof output.

Support parallel using OpenMP for the tree traversal phase. The task is divided to 2 ** par_depth parallel sub-tasks with the equal workloads. par_depth = -1: use ceil(log(num of threads)). par_depth = 0: no parallelism, i.e., sequential execution.

Evaluate on a contiguous subset of the full domain.

Evaluate the key on the range \([L, R]\). Store the outputs sequentially and accumulate the proof for this range. A successful verification guarantees (except with negligible probability, under the VDPF security assumptions) that the reconstructed function has at most one nonzero output for \(x \in [L, R]\); no guarantee is made outside this range.

Parameters
bParty index. False for 0 and true for 1.
Llower bound. The vdpf will be evaluated on the range \([L, R]\) of the full domain.
Rupper bound. The vdpf will be evaluated on the range \([L, R]\) of the full domain.
keyThe party's key returned by Gen().
ysPre-allocated output array. Its size must be at least \(R - L + 1\).
piProof output.

Key generation method.

Retries automatically on the rare bad-seed cases (cs all zeros or \(t_0 = t_1\) at the end): up to 128 attempts, each deterministically perturbing the seeds from the previous one. The effective seeds of the successful attempt are written back to s0s, so after a successful call s0s holds the seeds the returned keys carry.

Parameters
k0,k1Returned keys of the two parties.
s0s2 initial seeds. Users can randomly sample them. Written back with the effective seeds used by the successful attempt.
a\(a\).
b_buf\(b\). Will be clamped and converted to the group element.
retryWhether to retry with perturbed seeds on failure. If false, Gen returns 1 immediately after the first failed attempt.
Returns
0 on success, 1 if the first attempt failed (with retry = false) or all 128 attempts failed (with retry = true).

Both parties share the returned cws, cs, and ocw and differ in s0.

Proof accumulation method (Merkle fold).

Parallel alternative to Prove() over a fixed ordered sequence: hashes corrected per-point hashes into the leaves of a binary Merkle tree over the given sequence and folds adjacent nodes with the same hash level by level (an odd trailing node carries to the next level unchanged). The proof is {root, cs[2], cs[3]}, the same 64B shape as the chain's, so Verify() is shared. Every level is an OpenMP parallel batch honoring par_depth, so a par_depth of 0 makes the fold sequential. See doc/vdpf_merkle_fold_security.md.

Parameters
pi_tildesCorrected per-point hashes returned by Eval().
csReturned by Gen().
piProof output.
