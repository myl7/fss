Detailed Description

CPU point evaluation of FSS keys in the lean packed-key layout.

Author
Yulong Ming i@myl.nosp@m.7.or.nosp@m.g

The scheme classes keep each correction word in a 32 B slot (16 B s plus flag bytes), which the GPU needs for unmasked wide stores but which costs the host evaluator a 32 B stride per level and two loads where one would do. Run the matching *PackPoint() once per key after Gen(); it compacts a key to aligned 16 B correction words per level, packs the per-level tr bits into one word, and splits out the output correction word. The pack cost amortizes over every later point evaluation, same as Gen itself sits outside the timed loop.

The *EvalPoint() walks keep the seed in __m128i end to end (the Prg int4 interface is wrapped at the Gen boundary), pre-extract the query bits, and apply the control-bit corrections branchlessly via all-ones masks, so the per-level work is one PRG expansion plus a handful of XOR/AND ops.

The outputs are bit-exact with Dpf::Eval() / HalfTreeDpf::Eval(), for any Groupable Group and Prgable Prg, and cover the same input-domain widths as the host Eval, through __uint128_t.

Only for host side (x86-64 with SSE4.1; the PRG may additionally require AES-NI, e.g. Aes128MmoRaw).
